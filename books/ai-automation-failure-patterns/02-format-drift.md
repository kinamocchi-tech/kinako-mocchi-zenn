## 正しく書いたはずのファイルが、少しずつ違っていました

エージェントにファイルの読み書きを任せ始めた頃、筆者は形式の問題をほとんど心配していませんでした。JSON も YAML もライブラリが読み書きします。人間より正確なはずです。

最初の 3 か月で、この分類の記録は 19 件になりました。21 件のうち 9 割です。どれも派手な事故ではありません。日付が 1 日ずれる、コメントが消える、文字数の数え方が違う。ただ、どれも「ライブラリやコマンドに任せたのだから正しいはず」という前提の裏をかかれていました。

## 兆候：ずれ方には 4 つの型がありました

21 件の兆候を並べると、大半は次の 4 つの型のどれかに当てはまります（画像の縦横比の食い違いや、時間基準の異なる動画の結合のように、型の外にあるものも数件あります）。

**1. 書き戻すと何かが消える。** 人が読むための設定ファイルを、ツールが読み込んで 1 項目だけ更新し、書き戻しました。そのたびに、ファイル先頭の説明コメントが消えていました。標準的な YAML ライブラリはコメントをデータとして持たないので、読んで書けばコメントは残りません。複数行の説明文が、別の記法に変換されて戻ってくる事例もありました。

**2. 環境によって数え方が変わる。** 返信文の長さを「500 字以内」と判定するフックが、日本語 285 字の返信を止めていました。285 字は UTF-8 でおよそ 690 バイトです。フックが動く環境では文字コードの設定が空で、シェルの文字数カウントがバイト数を返していました。手元の対話環境では文字数を数えるので、再現しません。同じ形の記録に、時刻の判定があります。スケジューラーがサーバーの時刻帯（米国の太平洋時間）で現在時刻を読み、月曜の朝を「日曜の午後」と判定して、別の曜日のタスクを実行していました。

**3. 途中で切れる。** 数十 KB の JSON 出力を、確認のために先頭 300 行だけ表示させました。行の境界と JSON の構文の境界は一致しないので、4 万 7 千字あたりで構造の途中から切れ、後続の処理が解析エラーで止まりました。

**4. 型の外の値が混ざる。** 台本の各行に付ける感情ラベルは、動画を組み立てる側の型定義で値が決まっています。生成された台本に、その一覧に無い英単語の感情表現が混ざりました。古い形式で書かれたフィールドが新しい検査に引っかかる事例もあります。

4 つとも、エラーが出るのは「ずれた後」です。書いた瞬間には何も起きません。

## 3 層の原因

記録の原因欄を 3 層（直接の原因・それを許した仕組みの穴・穴が生まれた前提）に揃えると、層ごとに共通点が見えます。

| 層 | 共通していたこと |
|----|----------------|
| 直接 | ライブラリ・コマンド・環境の既定動作（コメント非保持、バイト数カウント、サーバー時刻帯、行単位の切り出し） |
| 仕組みの穴 | 書いたものを読み直して確かめる工程が無い。許される値の一覧が、検査できる場所に無い |
| 前提 | 「道具に任せた部分は正しい」という前提。エージェントが書いた内容は疑っても、道具が書いた形式は疑っていなかった |

3 層目が効いています。生成した中身は誰でも疑いますが、形式を道具に任せた瞬間に検査の対象から外れていました。

## 仕組みへの昇格：この分類は安く止まります

形式の崩れが後半にほとんど現れないのは、直し方が機械的で、しかも安いからです。筆者の運用での昇格は次の順でした。

| 段階 | やったこと | 効き方 |
|------|-----------|-------|
| 文書 | 「時刻は日本時間を明示する」「大きな出力はファイルに書いてから読む」と手順書に書く | 読まれれば効く。読み飛ばされると効かない |
| AI チェック | レビュー観点に「許可値の一覧と照合する」を足す | 一覧が手元にあるときだけ効く |
| フック・関数 | セッション開始時に時刻帯を固定する。書き込みは必ず「書く → 読み直す → 許可値と照合 → 置き換え」の関数を通す | 経路を通る限り、例外なく効く |

最後の段に上げた項目から、同じ形の記録は出なくなりました。この分類に限っては、2 回目を待たずに最初から関数やフックへ入れてしまってよい、というのが筆者の結論です。判定が「値が一覧にあるか」「読み直して一致するか」のように機械的に書けるからです。

## テンプレート 1：形式崩れチェックリスト

新しいファイル形式やスクリプトを足すときに、上から確認します。

- [ ] 人が読むファイルをプログラムで書き戻すとき、コメントや書式が保たれるライブラリを使っているか
- [ ] 書き戻したファイルを読み直し、書いたつもりのデータと一致するか確かめているか
- [ ] 列挙値（感情・状態・種別など）の許可一覧が、検査コードから参照できる 1 か所にあるか
- [ ] 必須フィールドの一覧が、検査コードから参照できる 1 か所にあるか
- [ ] 古い形式のデータを読んだときの扱い（変換するか、止めるか）を決めてあるか
- [ ] 文字数・長さの判定が、実行環境の文字コード設定に依存していないか（フックや無人実行の環境で一度試したか）
- [ ] 日時の判定・表示で、時刻帯を明示しているか
- [ ] 大きな構造化出力を、行単位で切り出して読んでいないか（ファイルに書いてから読む）
- [ ] 書きかけのファイルが残らないよう、一時ファイルに書いてから置き換えているか
- [ ] 検査が失敗したとき、元のファイルが無傷で残るか

## テンプレート 2：書き戻し検証の関数

チェックリストの 2・3・4・9・10 項目を 1 つの関数にまとめたものです。JSON を例にしていますが、読み直しと照合の部分は形式を問いません。

```python
"""書き込んだ JSON を読み直して検証してから置き換える（データ形式の崩れ対策）。"""
import json
from pathlib import Path

def write_verified(path, data, *, required=(), enums=None):
    """enums は {"フィールド名": {"許可値", ...}}。配列の各要素に適用する。"""
    p = Path(path)
    tmp = p.with_name(p.name + ".tmp")
    tmp.write_text(json.dumps(data, ensure_ascii=False, indent=2), encoding="utf-8")
    back = json.loads(tmp.read_text(encoding="utf-8"))      # 書いたものを読み直す
    problems = []
    if back != data:
        problems.append("読み直した内容が書いた内容と一致しない")
    items = back if isinstance(back, list) else [back]
    for i, item in enumerate(items):
        problems += [f"[{i}] 必須キー欠落: {k}" for k in required if k not in item]
        for field, allowed in (enums or {}).items():
            if field in item and item[field] not in allowed:
                problems.append(f"[{i}] {field}={item[field]!r} は許可値外")
    if problems:
        tmp.unlink()
        raise ValueError(f"{p}: " + " / ".join(problems))
    tmp.replace(p)                                          # 検証を通ってから置き換える
    return len(items)
```

正常なデータと、許可値外の感情ラベルを 1 件混ぜたデータの 2 通りで実行し、次の出力を確認しました（一時ディレクトリのパスは伏せています）。

```text
OK: 2
NG: <一時ディレクトリ>/a.json: [2] emotion='excited!!' は許可値外
元ファイルは無傷: {'id': 2, 'emotion': 'calm'}
```

2 回目の書き込みは失敗し、1 回目に書いたファイルがそのまま残っています。許可値の集合は、型定義を持つ側（この例では動画を組み立てる側）から読み込むようにしておくと、一覧が 2 か所に分かれて食い違う事故も防げます。

## 形式が正しいのに、中身が違う

書き戻しの検証と許可値の照合で止まるのは、形が崩れる失敗だけです。許可値の一覧に入っている感情ラベルが、場面に合っていないことまでは分かりません。読み直したデータが書いたデータと一致しても、書いたデータそのものが誤っていれば、検査は合格を返します。

運用 1 か月目の記録には、形式の失敗と同じくらい、形は正しいのに中身が崩れた失敗が並んでいました。画像の中の文字が化ける、読み上げが誤読する、外部サービスが仕様どおりに動かない。こちらは、許可値の一覧のような明快な照合先を持っていません。
