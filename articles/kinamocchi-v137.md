## Routinesとは？PCを閉じても動くAIコーディング

![セクションタイトル: Routinesとは？PCを閉じても動くAIコーディング](https://pub-2687e67855c941a0a1a9e1ad51ffc967.r2.dev/images/V137/044_section_title_routines.png)
- 🦜 きなこ：さて、UIの話の次はね、同じ日に発表された目玉機能、Routinesを見ていくよ
![図解: Routines = 保存された設定 + 自動実行](https://pub-2687e67855c941a0a1a9e1ad51ffc967.r2.dev/images/V137/046_routines_diagram.png)
- 🦜 きなこ：またそれ？でもね、これは結構すごい機能なんだよ。設定を保存して自動で動かすAIなの
![3要素図: プロンプト + リポジトリ + コネクタ → 自動実行](https://pub-2687e67855c941a0a1a9e1ad51ffc967.r2.dev/images/V137/049_three_elements_diagram.png)
- 🦜 きなこ：中身は3つでね、プロンプトと、リポジトリと、コネクタ。これをひとつの箱にまとめて、自動で走らせる仕組みなの
![比喩図: レシピ=プロンプト / 材料=リポジトリ / 調理器具=コネクタ](https://pub-2687e67855c941a0a1a9e1ad51ffc967.r2.dev/images/V137/051_cooking_analogy.png)
- 🦜 きなこ：そう、その例え結構いいと思う。レシピがプロンプト、材料がリポジトリ、調理器具がコネクタって感じね
![図解: ローカルPC vs Anthropicクラウド実行](https://pub-2687e67855c941a0a1a9e1ad51ffc967.r2.dev/images/V137/053_local_vs_cloud.png)
- 🦜 きなこ：ここが一番大事なポイントなんだよ。RoutinesはAnthropicのクラウドでAI自身が動くの
![イラスト: 閉じたノートPCの横でクラウド上のRoutinesが動作中](https://pub-2687e67855c941a0a1a9e1ad51ffc967.r2.dev/images/V137/054_closed_pc_cloud_running.png)
- 🦜 きなこ：だからね、ノートパソコンを閉じてても動き続けるって公式に書いてあるの。これがすごいの

## 3種類のトリガーで自動化を制す

![セクションタイトル: 3種類のトリガーで自動化を制す](https://pub-2687e67855c941a0a1a9e1ad51ffc967.r2.dev/images/V137/070_section_title_triggers.png)
- 🦜 きなこ：さっき「安全装置ある」って言ったよね。それも含めて、次はRoutinesの動かし方、トリガーを詳しく見ていくね
![3種類のトリガー一覧: Scheduled / API / GitHub](https://pub-2687e67855c941a0a1a9e1ad51ffc967.r2.dev/images/V137/072_trigger_overview.png)
- 🦜 きなこ：そうそう、その通り。Routinesには3種類のトリガーがあって、用途で使い分けるんだよ
![Scheduled: hourly / daily / weekdays / weekly](https://pub-2687e67855c941a0a1a9e1ad51ffc967.r2.dev/images/V137/073_scheduled_options.png)
- 🦜 きなこ：1つ目はScheduled。hourly・daily・weekdays・weeklyの4パターンから選べるの
![制約: 最短間隔 1時間](https://pub-2687e67855c941a0a1a9e1ad51ffc967.r2.dev/images/V137/075_min_interval_1hour.png)
- 🦜 きなこ：ちょっと待って。最短間隔は1時間で、それより短くはできないの。あとクレジットの消費にも気をつけてね
![CLI: /schedule update → クロン式入力](https://pub-2687e67855c941a0a1a9e1ad51ffc967.r2.dev/images/V137/077_cli_schedule_update.png)
- 🦜 きなこ：代わりにクロン式を使えば、もっと柔軟に設定できるの。CLIで「スラッシュスケジュール アップデート」って入力すれば変更できるよ
![ワンオフ実行: 1回のみ即時実行](https://pub-2687e67855c941a0a1a9e1ad51ffc967.r2.dev/images/V137/079_oneoff_execution.png)
- 🦜 きなこ：そう、よく知ってるね。あと「今すぐ1回だけ動かす」ワンオフ実行もできるの

## VM環境と実行制限

![セクションタイトル: VM環境と実行制限](https://pub-2687e67855c941a0a1a9e1ad51ffc967.r2.dev/images/V137/094_section_title_vm.png)
- 🦜 きなこ：さっき「安全装置」って言ったよね。それがVMの環境制限なの。Routinesはサンドボックスで動くんだよ
![図解: サンドボックス = 隔離された安全環境](https://pub-2687e67855c941a0a1a9e1ad51ffc967.r2.dev/images/V137/096_sandbox_diagram.png)
- 🦜 きなこ：IT用語では隔離された安全な実行環境のこと。子どもが砂場の中だけで遊ぶみたいに、外に影響を出さない仕組みなの
![VM仕様: Ubuntu 24.04 / 4vCPU / 16GB RAM / 30GB disk](https://pub-2687e67855c941a0a1a9e1ad51ffc967.r2.dev/images/V137/097_vm_specs.png)
- 🦜 きなこ：VMのスペックはね、Ubuntu 24.04ベースで、CPUが4コア、メモリ16GB、ストレージ30GBなの
![制約: ブランチ名は claude/ プレフィックス必須](https://pub-2687e67855c941a0a1a9e1ad51ffc967.r2.dev/images/V137/099_branch_constraint.png)
- 🦜 きなこ：ただし制約もあって、GitHubのブランチ操作は「claude/」で始まる名前のブランチしか使えないの
- 🦜 きなこ：そういうこと。AIが勝手に本番コードを書き換えるリスクを防ぐための仕組みなんだよ
![プラン別上限: Pro=5回 / Max=15回 / Team・Enterprise=25回](https://pub-2687e67855c941a0a1a9e1ad51ffc967.r2.dev/images/V137/102_plan_limits.png)
- 🦜 きなこ：1日に動かせる回数にも上限があるの。Proプランは5回、Maxは15回、TeamとEnterpriseは25回まで
