## ハーネスとは何か

- 🦜 きなこ：Microsoftの説明だと、モデルが知能を担当して、ハーネスはその周りの一式なの。指示、コンテキスト、実行環境、制御機能を与える層だよ
![たとえ図：料理人＝モデル／厨房＝ハーネス（レシピ・道具・火加減の管理・食材の置き場）](https://pub-2687e67855c941a0a1a9e1ad51ffc967.r2.dev/images/V314/013.png)
- 🦜 きなこ：厨房でたとえるね。モデルは腕のいい料理人。ハーネスは、レシピ、道具、火加減の管理、食材の置き場がそろった厨房なの
- 🦜 きなこ：料理人がどんなに上手でも、厨房がなければ、長い仕込みも、いくつもの料理の同時進行もできないでしょ
![カード：エージェントループ＝ツールを呼ぶ→結果を見る→次を決める、の繰り返し](https://pub-2687e67855c941a0a1a9e1ad51ffc967.r2.dev/images/V314/016.png)
- 🦜 きなこ：そう。ツールを呼んで、結果を見て、次を決める。この繰り返しを回すのがエージェントループなんだよ
![カード：モデルを替えても、同じ厨房（ハーネス）で作れる／タスクに合うモデルを選べる（Microsoftの説明）](https://pub-2687e67855c941a0a1a9e1ad51ffc967.r2.dev/images/V314/018.png)
- 🦜 きなこ：そこが今回の売りなの。タスクに合うモデルを選べて、ハーネスやスタックを切り替えなくていいと、Microsoftは説明してるよ
- 🦜 きなこ：GitHubのエンジニアリングチームだよ。発表の書き手も、FoundryのCVPとGitHubのCTOの2人なの

## 何が発表されたか

![発表の整理カード：Microsoft Copilot harness／Microsoft Foundry（Foundry Agent Service）／推論・ツール利用・長時間の複雑なタスク／フルマネージド](https://pub-2687e67855c941a0a1a9e1ad51ffc967.r2.dev/images/V314/026.png)
- 🦜 きなこ：Foundryの実行基盤として、Microsoft Copilot harnessが使えるようになったの。推論、ツール利用、長くて複雑なタスクをこなすエージェント向けだよ
- 🦜 きなこ：運用を向こうに任せるってことだよ。Microsoftが、エージェントループとサンドボックスを動かしてくれるの。サンドボックスは、隔離された安全な作業部屋のことね
![役割分担カード：Microsoftが運用＝エージェントループ・サンドボックス／利用者が用意＝指示・スキル・ツール・モデルの選択](https://pub-2687e67855c941a0a1a9e1ad51ffc967.r2.dev/images/V314/029.png)
- 🦜 きなこ：自分で用意するのは、指示、スキル、ツール、そしてどのモデルを使うかの選択。ここが役割分担なんだよ
![対応の整理カード：20以上のフロンティアモデル／BYOK（自分のAPIキーを持ち込める）／タスクに応じた自動ルーティング](https://pub-2687e67855c941a0a1a9e1ad51ffc967.r2.dev/images/V314/031.png)
- 🦜 きなこ：そのたとえでいいと思う。次はモデルの話。20以上のフロンティアモデルに対応していて、自分のAPIキーを持ち込むBYOKも使えるんだって
- 🦜 きなこ：そこは、発表の本文にモデル名の一覧がないの。使えるモデルは、公式の対応表で自分で確かめる必要があるよ
- 🦜 きなこ：ランタイムをRustに移植して、セッションのオーバーヘッドと、最初の文字が出るまでの時間が減ったと説明してるよ

## 使い方と安全面

![使い方の流れカード：①SKILL.mdに手順を書く ②azure.yamlでプロジェクト・スキル・エージェントを定義 ③azd deploy --all ④azd ai agent invoke](https://pub-2687e67855c941a0a1a9e1ad51ffc967.r2.dev/images/V314/043.png)
- 🦜 きなこ：Foundryの公式ブログの例だと、まずスキルを書くの。skillsフォルダの中のSKILL.mdに、手順を文章で書く形だよ
- 🦜 きなこ：近いよ。指示、スクリプト、関連する資料をひとまとめにして、いろんなタスクで使い回せるんだよ
- 🦜 きなこ：次にazure.yamlでエージェントを定義して、harnessのtypeにmicrosoft_copilot_previewを指定するの。previewの名前に注目だよ
![コマンドカード：azd deploy --all／azd ai agent invoke](https://pub-2687e67855c941a0a1a9e1ad51ffc967.r2.dev/images/V314/048.png)
- 🦜 きなこ：デプロイはazd deploy --all、呼び出しはazd ai agent invokeだよ
![入口カード：Foundryポータル／Foundry Toolkit for Visual Studio Code／GitHub Copilotアプリのプラグイン](https://pub-2687e67855c941a0a1a9e1ad51ffc967.r2.dev/images/V314/050.png)
- 🦜 きなこ：大丈夫、入口は複数あるの。Foundryポータル、VS Code向けのFoundry Toolkit、Copilotアプリのプラグインもあるよ
![ツール接続カード：MCPツール／Foundryツール／認証と承認は明示的に設定](https://pub-2687e67855c941a0a1a9e1ad51ffc967.r2.dev/images/V314/052.png)
- 🦜 きなこ：MCPのツールやFoundryのツールに接続できて、認証と承認は明示的に設定する形なの。何でも勝手に触る作りではないよ

## 料金と使い分け

![料金カード：ハーネス実行は12月1日より前は無料／12月1日から従量課金／サンドボックスの計算 vCPU時間あたり0.0994ドル／メモリ GiB時間あたり0.0118ドル](https://pub-2687e67855c941a0a1a9e1ad51ffc967.r2.dev/images/V314/058.png)
- 🦜 きなこ：ハーネスの実行は、12月1日より前は無料なの。12月1日から従量課金が始まるよ
- 🦜 きなこ：サンドボックスの計算は、vCPUの1時間あたり0.0994ドル、メモリは1GiBの1時間あたり0.0118ドルだよ
- 🦜 きなこ：電気代みたいなものだよ。作業部屋の頭脳とメモリを使った時間の分だけ払う仕組みなの
![カード：モデル推論と別課金のツールは、それぞれの料金／価格は地域や契約で変わることがある](https://pub-2687e67855c941a0a1a9e1ad51ffc967.r2.dev/images/V314/062.png)
- 🦜 きなこ：それとは別に、モデルの推論や、別に課金されるツールには、それぞれの料金がかかるの。価格は地域や契約でも変わることがあるよ
- 🦜 きなこ：無料なのは、ハーネスの実行分だけだよ。モデルの推論や別課金のツールは別料金だから、始める前に公式の料金ページで最新を確かめてね
![使い分けカード：ハーネスなしのプロンプトエージェント＝指示と対応ツールで足りる／ハーネス付き＝スキル・ファイル・サブエージェント・複雑なツール連携／Hosted agents＝フレームワークや実行ロジックを変えたい](https://pub-2687e67855c941a0a1a9e1ad51ffc967.r2.dev/images/V314/066.png)
- 🦜 きなこ：公式の整理だと、指示と対応ツールで足りるなら、ハーネスなしのプロンプトエージェント。スキルやファイル、サブエージェントが要るなら、ハーネス付きだよ
